# 2026-09-04

## WorkBuddy Linux 重打包：让 Linux 标题栏与 Windows 一致（5.5.2-5 已装入）

目标：Linux 顶部标题栏与 Windows 版一致（关于菜单 + 标题栏左槽含折叠/搜索/筛选）。

### 根因：renderer 里三处 Windows 专属硬分支
Linux 被当成非 Windows 非 Mac 第三态，拿不到 Windows 那套标题栏集成：

1. `firstMenuAsAbout: isWindows`，所以 Linux 第一菜单显示 WorkBuddy 而非 关于。
2. `ensureTitlebarLeftSlot()` 内 `if (!isWindows) return;`，Linux 不创建标题栏左槽。
3. `injectDesktopLayoutStyles` 的左槽/定位 CSS 全写在 `body[data-platform="windows"]` 下。
   注意：Linux 上 `data-platform` 属性根本不会被设置（只给 mac/windows 设），
   所以 Linux 选择器只能用 `body:not([data-platform="mac"]):not([data-platform="windows"])`。

4. 左槽空白的真正原因（关键）：portal 逻辑在 `renderer/assets/ui-docs-viewer-*.js`，
   不只判断槽是否存在，还硬性要求宿主是 Windows：
   - `if (!isHostWindows$1() || typeof document === "undefined") return;`（槽解析）
   - `const canPortalTitlebarActions = isHostWindows$1() && Boolean(accountUid);`
   - `if (!isHostWindows$1() || ... || !titlebarLeftSlot) return;`（图标数写入）

   `isHostWindows$1()` 即 `globalThis.__hostPlatform?.platform === "win32"`。

### 修补方案（已固化进 build.sh 的 stage_patch_app，三段）
- A. `main/menu-builder.js`：非 darwin 保持 setApplicationMenu(null)（原生菜单置空）。
- B. `renderer/assets/index-*.js`：
  - `firstMenuAsAbout: isWindows` 改为 `!isMac`（2 处）
  - `if (!isWindows) return;` 改为 `if (isMac) return;`（1 处，唯一）
  - 注入 Linux 左槽 CSS（幂等，靠注释「Linux: 复用 Windows 标题栏左槽」去重）
- C. `renderer/assets/ui-docs-viewer-*.js`（只放开标题栏布局）：
  - 放开槽解析 / portal 门禁 / 图标数写入 3 处
  - 隐藏页面内重复按钮 3 处（用 `|| true`、`&& false &&`、`&& false ?`），与 Windows 一致

重要：`isHostWindows$1()` 绝不能全局翻转。CommandDetail 命令安全、
isWorkspacePathTooLong 路径长度等依赖真实 Windows 语义，翻转会破坏 Linux 安全中心。

### 踩过的坑
- `stage_patch_app` 里同时 `python3 - "$TMP/app"` 又写 `root = os.path.join(sys.argv[1],'app')`，
  路径变成 `$TMP/app/app`，renderer 一个文件都没改到（构建不报错，静默失效）。
  正确写法：`root = sys.argv[1]`（解包目标已是 asar 根）。
- 校验已装 asar 不必抽包：asar 载荷是明文，直接
  `grep -ac "锚点" /opt/workbuddy/resources/app.asar` 即可。
- `grep -ac` 模式里的 `.` 是正则元字符，曾把「已注入」误判为 0；用中文注释做锚点最稳。
- `asar_tool.js`（纯 node，复刻 asar pickle 前缀）不在 git 跟踪里，一度丢失，
  已恢复并 cp 回工作区；缺失时可从 `/tmp/asar_tool.js` 找。
- 直接 `node asar_tool.js extract` 抽 283MB asar 常因等待批准/超时被取消，
  放进 build.sh 由用户批准后一次跑通更稳。

## 后续：左槽空白修复 + 屏蔽「发现应用」(5.5.2-5 ~ -7)

- 左槽空白根因：portal 逻辑除"槽存在"外还硬判 `isHostWindows$1()`，
  见 `ui-docs-viewer-*.js` 247844 / 247865 / 247868。已在 build.sh 加 section C 放开。
- `isHostWindows$1()` = `globalThis.__hostPlatform?.platform === "win32"`，**绝不能全局翻转**
  （CommandDetail 命令安全、isWorkspacePathTooLong 等依赖真实 Windows 语义）。
- 「发现应用」的真实身份：**不是** `workbuddy-topbar-actions` 的按钮，
  而是侧边栏应用切换器 `industry-template-switcher__trigger`
  （通用态显示"发现应用"，应用态显示应用芯片），见 `ui-docs-viewer-*.js` 117204。
  它盖住 workspace 标题/版本号。用户要求直接屏蔽 → 已加 CSS 隐藏
  `.industry-template-switcher__trigger--general:not(.industry-template-switcher__trigger--open)`
  （只隐藏关闭态，保留应用态芯片与已展开的 popover）。
- 走过的弯路：试图用 `.workbuddy-topbar-options { width:100% }` 的 flex 覆盖修重叠，无效，已撤。
- 版本号/标题重叠这类问题，先确认"到底是谁"再动手——用中文文案在源码里 grep
  （如 `发现应用`）定位组件，比猜 DOM 结构快得多。
