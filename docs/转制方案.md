# WorkBuddy CN → Linux deb 转制方案

> 本项目为非官方移植，仅供学习交流。WorkBuddy 版权归原开发方（腾讯）所有。

## 一、背景与目标

WorkBuddy（腾讯 CodeBuddy 的 AI 工作台产品）官方只发布了 Windows 与 macOS 安装包，
**没有 Linux 安装包**。本方案将其拆解后重新打包为 Linux deb 包，使其可在 Linux（Deepin/UOS/Debian）上运行。

## 二、源包分析结论（2026-08-31 实测拆包）

项目目录现有三个安装包：

| 包 | 格式 | 大小 | 说明 |
|----|------|------|------|
| `CodeBuddy-linux-x64-4.11.3-cn.deb` | Debian | 156MB | **已有 Linux 版**（Electron 18.1.7），与 WorkBuddy 不同产品 |
| `WorkBuddy-win32-x64-user-5.4.7.exe` | NSIS | 470MB | WorkBuddy Windows 版（源包内置 Electron 37.10.3，**转制时已替换为 39.2.7**） |
| `WorkBuddy-darwin-x64-5.4.7.dmg` | DMG | 514MB | WorkBuddy macOS 版 |

### 关键事实

- **WorkBuddy 与 CodeBuddy 是同源产品**：主入口同为 `@genie/agent-cli`（`lib/node/index.js`），
  bin 均为 `codebuddy` / `cbc-prewarm`，UI 为 Electron 工作台。
- **两个 WorkBuddy 源包都内置了全部 Linux 原生模块**（跨平台预编译）：
  - `node-pty-linux-x64/prebuilds/linux-x64/pty.node`
  - `koffi/build/koffi/linux_x64/koffi.node`
  - `@napi-rs/snappy-*`、`better-sqlite3` 等
  - Windows 包内 Linux 原生模块 16 个；macOS 包内 10 个
- **转制运行时统一使用 Electron 39.2.7（见 `build.sh` 的 `ELECTRON_VER`）**，与 Windows 包 ABI 一致。
  早期方案曾误判为 37.10.3；实测使用 Electron 37 会因 `better-sqlite3` ABI 不匹配导致 daemon 子进程崩溃、页面空白。
- **两个 WorkBuddy 的 app.asar 二进制不同**（自第 5 字节起即不同），各自针对平台构建。

### 结论：Windows 包是更合适的源

| 对比项 | Windows 包 ✅ 选中 | macOS 包 |
|--------|--------------------|----------|
| 解包工具 | NSIS → 7z 直接解压 | DMG → 需 7z/unsquashfs，并带出 `com.apple.cs.*` 代码签名资源分叉，需清理 |
| 目录结构 | **扁平**（顶层即 resources/ + *.pak + 主程序），取件简单 | `.app/Contents/Frameworks/*.framework` 深层嵌套，结构复杂 |
| Linux 原生模块 | 16 个（更全） | 10 个 |
| 需清理的冗余 | 少量 `.dll`/`.bat` | Framework、icns、xattr 资源分叉（清理量大） |

**选 Windows 包的理由**：结构扁平、取件直接、Linux 原生模块最全；macOS 包虽有同样的
JS 层，但 .app 嵌套结构与代码签名资源分叉会显著增加转制与清理成本，且无额外收益。

## 三、转制原理

WorkBuddy 是 Electron 应用，转制核心是**保留跨平台的 JS 资源层，替换平台相关的
Electron 运行时与原生二进制**：

| 组件 | 来源 | 作用 |
|------|------|------|
| `app.asar` + `app.asar.unpacked` | WorkBuddy **Windows** 安装包 | 应用 JS 层、UI、内置插件、CLI 代理 |
| Electron **39.2.7** Linux x64 运行时 | 从 Electron 官方/镜像下载 | Chromium 运行时、主进程二进制（ELF） |
| 顶层资源（`*.pak`/`icudtl.dat`/`snapshot_blob.bin`） | WorkBuddy Windows 包 | Chromium 资源文件（跨平台共用） |
| Linux 原生 `.node`/`.so` 模块 | WorkBuddy Windows 包（已内置）+ 重编译 | 终端、koffi、sqlite 等原生能力 |

## 四、目录结构（目标 deb）

```
├── build.sh              # 唯一构建入口：拆包 → 组装 deb-pkg → 原生模块 → 桌面集成 → 构建 deb
├── docs/                 # 转制方案与说明文档
├── deb-pkg/              # 打包目录
│   ├── DEBIAN/
│   │   ├── control       # 包元信息（依赖/版本/体积）
│   │   └── md5sums       # 构建时生成（不纳入版本库）
│   ├── opt/
│   │   └── workbuddy/
│   │       ├── workbuddy            # Linux 启动脚本（软链 /usr/bin/workbuddy）
│   │       ├── workbuddy-bin        # Electron 39.2.7 主二进制（ELF）
│   │       ├── resources/           # app.asar + app.asar.unpacked（来自 Windows 包）
│   │       ├── *.pak / icudtl.dat / snapshot_blob.bin
│   │       └── locales/
│   └── usr/              # 桌面集成产物（图标 / .desktop / 软链，构建时生成）
└── extracted-win/        # （可选）Windows 包解压目录
```

## 五、构建阶段设计

### 阶段 1/5：拆包 Windows 安装包

1. 探测格式：NSIS（`file` 输出 `Nullsoft Installer`）。
2. `7z x` 解压外层 NSIS → 得到 `$PLUGINSDIR/app-64.7z`（实际应用体）。
3. `7z x` 解压 `app-64.7z` → 顶层含 `WorkBuddy.exe`、`resources/`、`*.pak`、`icudtl.dat` 等。
4. 校验关键产物存在：`resources/app.asar`、`resources/app.asar.unpacked`。

### 阶段 2/5：获取 Electron 39.2.7 Linux x64 运行时

- 从 Electron 官方 releases 下载 `electron-v39.2.7-linux-x64.zip`（镜像加速，失败回退 GitHub）。
- 解压得到 `electron`（主二进制）、`chrome-sandbox`、`chrome_crashpad_handler`、`*.pak`、`locales/`、`*.so`、`ffmpeg.so`、`libvulkan.so.1`、`vk_swiftshader_icd.json` 等。

### 阶段 3/5：组装 deb-pkg

1. 复制 Electron 运行时二进制与 Chromium 资源到 `opt/workbuddy/`。
2. 从 Windows 包复制 `resources/`（app.asar 与 unpacked）到 `opt/workbuddy/resources/`。
3. 复制 Windows 包内的 Linux 原生模块（`node_modules/*linux*`、`koffi/linux_x64`、`better-sqlite3` 等）。
4. 写入启动脚本 `workbuddy`（处理 `--no-sandbox` 回退、`--disable-dev-shm-usage` 等）。
5. 补丁 `app.asar` 内 main.js / product.json：`buildPlatform` 置 `linux`，标题栏强制 custom（参照 traework 项目已踩坑的标题栏白块问题）。

### 阶段 3.5/5：重编译 Linux 原生模块

- `better-sqlite3`：Windows 包带的是 win32-x64 的 `.node`，daemon 以 Electron `RUN_AS_NODE` 启动，
  必须换成对应 ABI 的 Linux ELF。用以下命令重编译（版本锁定 12.8.0，目标 39.2.7）：

  ```bash
  npm_config_runtime=electron npm_config_target=39.2.7 \
  npm_config_disturl=https://electronjs.org/headers npm_config_arch=x64 \
  npm install better-sqlite3@12.8.0 --no-save
  ```

  并把 `bindings`、`file-uri-to-path` 一并复制到 `app.asar.unpacked/node_modules/`。
- 其余 Windows 专属原生模块（`qimei-node` / `turing-sdk` / `wechat-copydata-decoder` 等）
  按代码逻辑安全降级，暂不替换（详见第九章）。

### 阶段 4/5：桌面集成

- 生成多尺寸图标（`usr/share/icons/hicolor/`）。
- 写 `usr/share/applications/workbuddy.desktop`（桌面入口 `WorkBuddy`，`Exec=workbuddy`）。
- 软链 `/usr/bin/workbuddy` → `/opt/workbuddy/workbuddy`。
- 修正启动脚本权限 755、`chrome-sandbox` setuid。

### 阶段 5/5：构建 deb

- 递归生成 `md5sums`、重算 `Installed-Size`、自增 `Version`。
- `dpkg-deb --build --root-owner-group` 产出 `com.xydw.workbuddy_5.4.7-x_amd64.deb`。

## 六、已知风险与对策（来自 traework-win-to-linux 踩坑）

| 风险 | 对策 |
|------|------|
| Linux 下标题栏白块/丢失 | 补丁 main.js 中 titleBarOverlay 守卫，强制 custom（Linux 分支），启动参数 `--title-bar-style=custom` |
| `--no-sandbox` 回退 | postinst 设置 chrome-sandbox setuid；启动脚本检测并自动追加 `--no-sandbox` |
| 设备注册/应用身份错配 | 保留 WorkBuddy 自身 `install-manifest.json` / 应用身份，勿用 CodeBuddy 的 |
| Electron 运行时缺失 | 从官方/镜像下载，脚本内置版本号与校验 |
| 文件描述符上限 | 启动脚本 `ulimit -n 65535` |
| better-sqlite3 ABI 不匹配（页面空白/daemon 崩溃） | 阶段 3.5 重编译对应 ABI 的 Linux `.node` |
| 启动报 FATAL 找不到 crashpad | 必须复制 `chrome_crashpad_handler` 到 `opt/workbuddy/` |

## 七、待确认事项（已落地结论）

1. **是否需要玲珑 uab 版**：当前仅 deb 版，玲珑转换按需再做。
2. **Electron 运行时来源**：已锁定 **39.2.7**（npmmirror 镜像优先，失败回退 GitHub）。
3. **包名/安装路径**：`opt/workbuddy`，产品名 `WorkBuddy`，命令 `workbuddy`。
4. **是否保留内置插件**：保留 WorkBuddy 自带插件；Windows/macOS 专有原生模块按第九章降级。

## 九、已落地关键修复（实测验证）

| 问题 | 现象 | 修复 |
|------|------|------|
| Electron 版本误判 | 旧方案用 37，daemon 因 better-sqlite3 ABI 崩溃、页面空白 | 锁定 **39.2.7**，与 Windows 包 ABI 对齐 |
| better-sqlite3 ABI | daemon 子进程 SIGABRT | npm 重编译 12.8.0（target=39.2.7），覆盖 `app.asar.unpacked` 内 `.node` |
| 缺失运行时依赖 | 启动报 `Cannot find module 'bindings'` | 复制 `bindings` / `file-uri-to-path` 到 unpacked |
| crashpad 缺失 | 启动 FATAL: crashpad handler not found | 复制 `chrome_crashpad_handler` |
| 标题栏白块 | Linux 下标题栏空白 | `--title-bar-style=custom` + main.js titleBarOverlay 守卫 |
| 无 root 沙箱 | 非 root 启动失败 | 启动脚本检测 `chrome-sandbox` 无 setuid 时自动 `--no-sandbox` |
